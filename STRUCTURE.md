# Как устроен сайт

Этот файл про страницы: из чего они собираются, где править тексты и работы, какие есть блоки и стили.
Про сервер, сборку, публикацию, форму и аналитику — в [README.md](README.md).

## Коротко

- Сайт статический: готовые HTML-страницы, общие стили и скрипты в `fresh/`, медиа в `fresh/media/` и `Video/`.
- Раздел «Работы» (`/works/…`) и шапка на всех страницах **собираются скриптами** из `tools/`.
  Руками эти HTML не правят: при следующей сборке правка пропадет.
- Тексты и данные работ лежат в двух файлах, их можно править без кода:
  - `texts/works.md` — все работы (название, теги, описание, обложки, ролики, ссылки);
  - `texts/tags.md` — заголовки и подзаголовки страниц тегов.
- Главная, кейсы и страница 404 хранятся в старом виде в `_src/`. Кейсы собираются в `/works/<кейс>/`, их картинки и видео лежат в `cases/<кейс>/media/`.
  Сборка берет их оттуда и ставит новую шапку. Поправить текст главной или кейса — правим в `_src/…`.

## Как внести правку

1. Поправить `texts/works.md`, `texts/tags.md`, `_src/…` или код в `tools/`.
2. Пересобрать страницы:

   ```bash
   python tools/build_pages.py
   ```

3. Посмотреть локально (`npm run dev`, адрес http://localhost:5173), проверить телефон.
4. Проверки и сборка из README: `npm run check`, тесты, `npm run build`.
5. Публикация — push в `main` (см. README): это сразу выкладка на new.petrovichbrothers.ru.

Нужен Python 3.10+ без дополнительных библиотек. Для нарезки роликов — ffmpeg.

## Состав страниц

| Адрес | Что это | Кто собирает |
|---|---|---|
| `/` | Главная (содержание из `_src/index.html`, новая шапка) | `make_shell.py` |
| `/works/<кейс>/` | Кейсы (из `_src/cases/…`, новая шапка; медиа в `cases/<кейс>/media/`) | `make_shell.py` |
| `/404.html` | Страница «Такой страницы нет» (из `_src/404.html`) | `make_shell.py` |
| `/works/` | «Работы, которыми мы гордимся»: заголовок, теги, все работы | `make_works.py` |
| `/works/<тег>/` | 13 страниц тегов: видео, мэппинг, музеи, выставки… | `make_tags.py` |
| `/works/interactive/` | Посадочная «Интерактивные экспонаты» (те же модули, все работы крупно) | `make_landing.py` → `make_tags.build()` |
| `/works/khakasia/` | Проект «Стенд Республики Хакасия» | `make_project_khakasia.py` |
| `/works/khakasia/stol/` | Экспонат «Интерактивный стол» (из `_src/cases/khakasia/`) | `make_stol.py` |
| `/works/khersones/` | Проект «Зал Черноморского флота» | `make_project_khersones.py` |

Старые адреса (`/cases/<кейс>/`, `/cases/hersones/`, `/cases/khakasia/`, `/projects/…` со старого сайта) перенаправляются
на новые в `server/redirects.mjs`.

## Данные

### `texts/works.md` — работы

Каждая работа — раздел `## <код>` и строки «Поле: значение». Описание полей — в начале файла. Главное:

- **Что делаем / Для кого** — коды тегов через запятую. По ним работа попадает на страницы тегов.
- **Проект** — код проекта (`khakasia`, `khersones`) у экспонатов большого проекта.
- **Описание** — для крупной карточки, начинается с вопроса: «Как …? Ответ».
- **Где и когда** — серая строка под описанием крупной карточки (если пусто — год).
- **Обложки** — одна крупная (`Обложка крупной`, широкая) и одна маленькая (`Картинка`, для плитки)
  на весь сайт. Маленькую делаем из крупной: та же картинка, сверху и снизу черные поля.
- **Ролики** — `Превью` для плитки, `Крупное видео` и `Крупное видео, телефон` для крупной карточки.
- **Ссылка** — куда ведет карточка. Если своей страницы нет, но есть `Обзор`, карточка открывает видео.
- **Скрыть: да** — работа есть в данных, но на сайте не показывается.

### `tools/works.json` — теги и проекты

- `tags.what` — «Что делаем»: `[код, название]`.
- `tags.who` — «Для кого»: `[код, название, дательный падеж]` (дательный — в строке тегов на «Работах»).
- `projects` — большие проекты: название, короткое имя для пути, «где и когда», описание, обложки, адрес.

### `texts/tags.md` — тексты страниц тегов

Заголовок, подзаголовок и (необязательно) заголовок вкладки. Какие страницы тегов полные
(открыты для поиска, с ценами и вопросами) и какая на них вставка «Из опыта» — в `tools/make_tags.py` (`FULL`).
Остальные пока закрыты от поиска (`noindex`).

У музеев, выставок, застройщиков, интерактивных экспонатов и видео в `texts/tags.md` заданы свои подписи карточек, блок «Что берем на себя»,
текст «Из опыта», вопросы, обращение и связанные направления. Поле `Цены: нет` скрывает
общий блок цен. Эти поля необязательны: остальные подборки сохраняют общие блоки.
Название, описание и подпись карточки можно переопределить только в подборке через поля `Карточка <код>, Название / Описание / Подпись`. Данные самой работы остаются в `texts/works.md`.
Поле `Работы` задает точный состав и порядок подборки кодами через запятую.
Без этого поля сохраняется автоматический подбор по тегам. Повторы и неизвестные коды останавливают сборку.
Пересобрать одну страницу без изменения остальных: `python tools/make_tags.py exhibitions` (или `museums`).
Локальные стили музеев и выставок находятся в `fresh/museums.css` и `fresh/exhibitions.css`.
Для застройщиков, интерактивных экспонатов и видео используется `fresh/landings.css`.
После изменения этого файла поднимите `?v=` для него в `make_tags.py` и пересоберите три страницы.

Интерактивная посадочная теперь берет текст и подборку из раздела `interactive` в `texts/tags.md`.
Все ее работы показаны крупно; сохранены якоря `#khakasia`, `#mengiry`, `#shturval`, `#scanner`.
`make_tags.py` ничего не записывает при импорте; `make_landing.py` вызывает `build("interactive")`.
Можно собрать все три страницы одной командой: `python tools/make_tags.py stand-builders interactive video`.

Поле `Стоимость` выводит отдельный блок перед вопросами. На пяти переработанных посадочных вопрос о стоимости перенесен туда.
Когда будет готова страница «Цены и услуги», добавьте в нужные разделы `texts/tags.md` поле
`Ссылка на цены: prices/` (или ее фактический адрес) и при необходимости `Текст ссылки на цены`.
До этого ссылка не выводится. Сборщик проверяет, что указанный адрес ведет на существующий `index.html`.
Этот блок не зависит от общего переключателя `PAGES_READY` и не включает другие незавершенные страницы меню.

## Сборщики (`tools/`)

- `v2parts.py` — общие куски. Загружает данные, содержит класс `Page` и правила:
  - `typo()` — неразрывные пробелы после коротких слов, слова через дефис не разрываются;
  - `Page.header()` — шапка с меню «Работы ▾» (большая панель «Что делаем» / «Для кого»);
  - `Page.msheet()`, `tsheet()`, `sheet()` — шторки снизу на телефоне: меню, все теги, экспонаты проекта;
  - `Page.landing_nav()`, `sub_switch()`, `sub_crumbs()`, `ctx_tags()` — переключатель «Работы → тег ⌄»,
    вторая строка шапки и подсказка «где ты» на телефоне;
  - `Page.works_mix()` — список работ: крупные карточки и плитка (правило ниже);
  - `Page.big_card()`, `tile()` — крупная карточка «как экспонат» и плитка;
  - `Page.plate()` — вставка «Из опыта на площадках» (кусок разбора «10 ошибок»);
  - `Page.project_photo()` — общий кадр проекта под заголовком (появляется, только если файл есть);
  - `Page.next_work()`, `seealso()`, `faq()` — «Следующая работа», «Смотрите также», частые вопросы;
  - `Page.contact()` — призыв в черном блоке контактов под тему страницы (`cta`: музей, медиа или общий);
  - `Page.finish()` — подключает шторки, кружок «Контакты», `v2.css`/`v2.js`, класс страницы.
- Переключатели в начале `v2parts.py`:
  - `V2CSS`, `V2JS` — версии стилей и скрипта. **После правки `fresh/v2.css` или `fresh/v2.js` поднять версию**
    и пересобрать: сервер кэширует файлы с `?v=` надолго, иначе посетители увидят старые.
  - `PAGES_READY` — пока `False`, в меню нет «Услуг», «Цен», «О студии» и ссылок на них.
    Когда страницы появятся — `True` и пересобрать.
- `make_*.py` — по одному на тип страницы (см. таблицу выше). `build_pages.py` запускает все.

### Правило крупных карточек

На «Работах» и страницах тегов крупно показываются: первая работа, одна в середине на длинных страницах
(от 9 работ) и последняя, если в плитке ей не хватило пары. Остальные — плиткой в две колонки.
Порядок: сначала экспонаты больших проектов, потом отдельные работы, новые выше.
На телефоне крупные карточки выглядят так же, как плитки. «Интерактивные экспонаты» — исключение: там все крупно.

## Стили и скрипты (`fresh/`)

- `fresh.css`, `fresh.js` — основа сайта (главная, карточки экспонатов, ролики, курсор «Смотреть»,
  окно с видео, панель контактов, форма). Подключены на всех страницах.
- `case.css`, `case.js` — старые кейсы.
- `v2.css`, `v2.js` — новая структура поверх основы. Разделы `v2.css` подписаны комментариями:
  шапка, теги, частые вопросы, кружок «Контакты», шторки на телефоне, вставка «Из опыта»,
  страница экспоната, «Работы», переключатель тега, вторая строка шапки, подсказка «где ты»,
  «Следующая работа», страница проекта, страницы тегов, работы вперемешку, общий кадр проекта.
- `v2.js`: шапка прячется при прокрутке вниз; шторки (закрытие свайпом, кнопкой «Назад», по фону);
  меню «Работы» по наведению; показ переключателя тега тем, кто пришел с сайта; ролики плиток
  при наведении, а на телефоне — пока плитка на экране; рамки фокуса только с клавиатуры.
- `cookies.js` — служебный.

Ролики в карточках грузятся, только когда подъезжают к экрану, и играют, только пока видны.

## Медиа

| Что | Размер | Где |
|---|---|---|
| Маленькая обложка (плитка) | 1300 × 1000 или 650 × 500 | `Картинка` в `works.md` |
| Крупная обложка | 1280 × 720 и шире | `Обложка крупной` |
| Ролик плитки (превью) | 720 по ширине, 8–15 с, без звука; можно тот же файл, что и крупный (см. ниже) | `Превью` |
| Крупный ролик | 1280 × 720 (или 1600 × 800), без звука; лучше в трех размерах (см. ниже) | `Крупное видео` |
| Крупный ролик для телефона | 720 × 900, вертикальный | `Крупное видео, телефон` |
| Полный обзор | как есть, со звуком | `Обзор`, папка `Video/` |
| Общий кадр проекта | 2400 по ширине, webp | `fresh/media/khakasia-stand.webp`, `khersones-hall.webp` |

Ролики кодируем в H.264 с `-movflags +faststart` (проверка сборки требует начало файла в начале).

**Ролик в нескольких размерах.** Рядом с основным файлом `x.mp4` (1280 по ширине) кладем `x-720.mp4` и `x-1920.mp4`.
В `works.md` пишем только `x.mp4`. Сборка сама находит соседние размеры и ставит атрибут `data-widths="1280 720 1920"`
(первая цифра — ширина основного файла). `fresh.js` при загрузке берет наименьший файл, которого хватает на ширину блока
на экране × плотность пикселей (не больше ×2); при экономии трафика — самый маленький. Один набор файлов годится и для крупной
карточки, и для плитки, поэтому в `Превью` можно указать тот же `x.mp4`. Телефонная вертикаль `x-m.mp4` (720 × 900) — отдельно.
Если соседних размеров нет, ролик работает как раньше, одним файлом.
Так же работает и отдельное превью плитки: основной `x-preview.mp4` (720) и рядом `x-preview-1280.mp4` для ретины.
Ширина основного файла может быть любой (например, 1600 у Таймлайна и Кораблестроения, рядом `-720`).
Соседние размеры режем из исходника в высоком разрешении тем же отрезком и тем же кадрированием, что основной файл,
и проверяем, что кадры совпадают. Растягивать 1280 до 1920 нельзя. Исходники старых обзоров в 1920 лежат
в `Petrovich brothers/Видео с сайта/`.

Как собрать из мастера (ProRes или PNG) — цвет Rec.709 с пометкой в файле, без звука:

```
T="-c:v libx264 -preset slow -profile:v high -pix_fmt yuv420p -color_primaries bt709 -color_trc bt709 -colorspace bt709 -an -movflags +faststart"
ffmpeg -i master.mov -vf "scale=720:-2:flags=lanczos"   -crf 23 $T x-720.mp4
ffmpeg -i master.mov -vf "scale=1280:720:flags=lanczos" -crf 23 $T x.mp4
ffmpeg -i master.mov -vf "scale=1920:1080:flags=lanczos" -crf 24 $T x-1920.mp4
ffmpeg -i master-vert.mov -vf "scale=720:900:flags=lanczos" -crf 22 $T x-m.mp4
```

**Обзоры** (`Video/`, со звуком) — так же: рядом с `x.mp4` лежат `x-720.mp4`, `x-1280.mp4`, `x-1920.mp4` (какие есть).
Шаг сборки `tools/add_video_widths.py` ставит кнопкам обзора `data-video-widths`, окно обзора берет размер по ширине окна
браузера × плотность пикселей. Отдельная версия для телефона (`data-video-mobile`) по-прежнему главнее.
Звук при пережатии — AAC 128k. Настройки: 720 — `-crf 24 -maxrate 1000k`, 1280 — `-crf 25 -maxrate 700k` (обзоры
сняты и смонтированы спокойно, при 0,7 Мбит/с на экране 1280 не отличить от 1920), 1920 — `-crf 23 -maxrate 3500k`.
Меньший размер, который весит больше 70–85% основного, не кладем: выигрыша нет (так вышло у Кораблестроения в 1280).

Размером считается только файл, у которого реальная ширина равна числу в имени: `yantarny-2019.mp4` — другой ролик.
Версия в адресе (`?v=`) у основного файла считается вместе с соседними размерами (`scripts/build.mjs`), поэтому
перезаливать соседний размер можно отдельно — браузер не застрянет на старом.

Ориентир по весу для ролика 10–12 с: 720 — около 1 МБ, 1280 — 2,5–3 МБ, 1920 — 4–6,5 МБ.
Если в исходнике вшиты субтитры, кадр режем так, чтобы их не было.

## Как добавить…

**Работу.** Добавить раздел в `texts/works.md` (скопировать похожий), положить картинку и ролики,
пересобрать. Работа сама появится на «Работах» и на страницах своих тегов.

**Тег.** Добавить строку в `tools/works.json` (`what` или `who`) и раздел в `texts/tags.md`, пересобрать.

**Проект с отдельной страницей.** Добавить проект в `tools/works.json`, экспонатам в `works.md` указать
`Проект`, сделать сборщик по образцу `make_project_khersones.py` и добавить его в `build_pages.py`.
Старому адресу, если он был, — перенаправление в `server/redirects.mjs`.

**Новую папку верхнего уровня** (как `works/`) — прописать в трех местах, иначе выкладка упадет:
`Dockerfile` (COPY), `scripts/build.mjs` (entries) и `server/site.mjs` (directories).

## Правила текста

- Без «ё» и без длинных тире.
- Ударение в «Пе́трович» сохраняем.
- Бренды и названия событий пишем полностью, но без перечислений ради поиска.
- Текст при наведении не синеет: подчеркивание выезжает.
- Коротко.

## Что важно знать

- Проверка сборки (`npm run verify:build`) падает на любой битой локальной ссылке. Поэтому ссылок
  на еще не сделанные страницы быть не должно (см. `PAGES_READY`).
- Карта сайта `sitemap.xml` пока собирается сборкой из старых кейсов; страниц `/works/` в ней нет.
- Скрипт проверки сборки и тесты деплоя не работают на Windows (пути и bash); на GitHub проходят.
