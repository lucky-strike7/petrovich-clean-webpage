# Petrovich Brothers

Сайт на HTML, CSS и обычном JavaScript. Vue и Nuxt не нужны: сервер отдаёт готовые страницы, а JavaScript отвечает за видео, анимации и формы. На сервере используется Nodemailer. esbuild нужен только при сборке, чтобы минифицировать CSS и JavaScript. Дизайн и тексты редактируются в исходных HTML/CSS/JS; `dist/` генерируется автоматически.

## Локально

Нужен Node.js 22.14 или новее.

```sh
npm ci
cp .env.example .env
npm run dev
```

Открыть http://127.0.0.1:5173/. Без реквизитов доставки форма вернёт понятную ошибку и не покажет ложный успех. Секреты в `.env` не попадают в Git, сборку и публичные файлы. Существующие переменные `NUXT_SMTP_*`, `NUXT_TELEGRAM_*`, `NUXT_CONTACT_RECIPIENTS` тоже поддерживаются для перехода со старого backend.

## Проверка и сборка

```sh
npm run check
npm test
npm run build
npm run verify:build
NODE_ENV=production npm start
```

Тесты используют подставную доставку: сообщения не отправляются. Сборка содержит только новый сайт и его медиа, без старых версий, инструментов, `.git` и серверных файлов. Она добавляет версии к ресурсам и готовит gzip/Brotli для текста. Сервер поддерживает ETag, HEAD, перемотку видео через Range и корректный 404. На production он раздаёт только `dist/` и `/api/contact`.

## Работа вдвоём через GitHub

Основной репозиторий: https://github.com/lucky-strike7/petrovich-clean-webpage. Общая актуальная версия — `main`. Для push нужен доступ на запись от владельца.

Перед новой работой:

```sh
git switch main
npm run update
git switch -c codex/my-change
```

После изменений:

```sh
npm run check
npm test
npm run build
git add <конкретные-изменённые-файлы>
git commit -m "Описание изменения"
git push -u origin codex/my-change
```

Создать pull request в `main`. После объединения Артём и Арсений обновляют свои локальные `main` командой `npm run update`. Она откажется работать при незакоммиченных файлах, в другой ветке или при расходящейся истории; force/reset/stash автоматически не применяются. Для получения свежего `main` в уже начатую рабочую ветку: `git fetch origin`, затем `git merge origin/main`, разрешить возможные конфликты и повторить проверки. Пуш рабочей ветки не публикует сайт. После объединения в `main` GitHub Actions запускает проверки и автоматическую публикацию.

Не меняйте исходники внутри `dist/` и не копируйте правки из старого сайта обратно в этот репозиторий. Все изменения нового сайта живут здесь.

## Форма

`POST /api/contact`, JSON `{ "phone": "+79150000000", "consent": true }`. Успех — только HTTP 200 и `success: true` после подтверждения хотя бы одного канала доставки. Неверные данные, отсутствие согласия, чужой Origin, слишком большой запрос и превышение лимита возвращают ошибку. Клиент блокирует повторный submit на время запроса.

В `.env` заполнить SMTP и/или Telegram. Не вставлять токены в HTML или JavaScript. По умолчанию используется реальный адрес соединения. `CONTACT_TRUST_PROXY=true` включать только за доверенным reverse proxy, который очищает входящие forwarded-заголовки; порт приложения не публиковать напрямую. Лимиты хранятся в памяти одного процесса; перед несколькими репликами потребуется общий limiter.

## Метрика

Сохранён счётчик **46078563**. Он запускается автоматически только на `petrovichbrothers.ru` и `www.petrovichbrothers.ru`; localhost, GitHub Pages и тестовые поддомены исключены. Плашка выбора аналитики не показывается. Вебвизор не записывает клавиши поля телефона (`ym-disable-keys`). В параметры целей не передаются телефон или данные заявки.

Проверить/добавить в кабинете цели типа «Целевое событие» с идентификаторами:

- `callback_success` — подтверждённая отправка заявки;
- `contact_telegram`, `contact_phone`, `contact_email` — переход к контакту (ещё не обращение);
- `video_open` — открытие обзора.

Источник API: https://yandex.ru/support/metrica/ru/objects/reachgoal. Код событий готов; создание целей и фактическое получение событий в аккаунте требуют отдельной проверки на боевом домене. Опубликованное описание аналитики должно соответствовать фактическому поведению сайта.

## Размещение

Есть Dockerfile с Node 24 и отдельной production-стадией. Собрать `docker build -t petrovich-static:<commit> .`, передать секреты окружением или защищённым env-file и поставить за существующим HTTPS reverse proxy. Контейнер слушает 3000; наружу — только proxy. Историю счётчика и существующую почту не менять.

До переключения проверить на отдельном адресе: главную, кейс, документы, медиа, мобильную шторку, работу клавиатуры, ошибку формы и согласованную контрольную доставку. Старые страницы по решению владельца не входят в новый сайт. Для прежних адресов действует карта 301 из `server/redirects.mjs`; остальные URL получают настоящий 404. Служебные приложения вроде `/pb-search`, если они размещены отдельно, не удалять вместе с каталогом старого сайта. Сохранить предыдущий image/release для отката. Публикацией изменений `main` управляет GitHub Actions; подробности ниже.

## FirstVDS: основной и архивный сайты

Сервер: `109.172.100.87`. Текущая схема маршрутизации — файловый provider Traefik, `/srv/docker/traefik-global/dynamic/routes.yml` (JSON). Docker labels здесь не управляют маршрутами.

`deploy/compose.yml`: новый сайт `pb-website:3000` и архивный gateway `pb-archive-gateway:8080`. Образ задаётся переменной `PB_RELEASE`. Секреты остаются в существующем защищённом `.env` на сервере; в Git и образы они не входят. Старый контейнер `petrovichbrothers-web-1` сохраняется целиком.

Архив `old.petrovichbrothers.ru` использует `deploy/archive.conf`: обязательный `X-Robots-Tag: noindex, nofollow, noarchive`, отключение внешних аналитических скриптов через CSP, без старого sitemap. robots.txt разрешает роботу открыть страницу и прочитать noindex. Это запрет индексации, а не защита доступа. Документация: https://developers.google.com/search/docs/crawling-indexing/block-indexing.

При обновлении сначала собрать image с `--build-arg BUILD_COMMIT=<sha>`, проверить отдельный контейнер без публичного маршрута и только затем пересоздать `web` с `PB_RELEASE=<image> docker compose -f deploy/compose.yml up -d web`. Основной сервис Traefik `pb` направляется на `http://pb-website:3000`; маршруты `/pb-search`, почты и других сайтов сохраняются. До переключения сохранить образ, снимок маршрутов и текущую ссылку на release. Откат — вернуть прежний `pb` backend или предыдущий проверенный image.

## Перенаправления старых адресов

Сервер возвращает 301 для GET/HEAD до поиска статического файла. Query string сохраняется без пересборки, включая UTM, yclid, повторяющиеся параметры и кодирование. Якорь раздела добавляется после query string. На архивном домене продолжает работать прежний сайт, эта карта к нему не применяется.

| Старый путь (также с завершающим /) | Новый путь |
| --- | --- |
| /video-content, /videocontent, /testimonials, /cyberbug, /blog-list, /p | / |
| /about-us | /#process |
| /contacts, /contact | /#contact |
| /projects/khakasiya | /cases/khakasia/ |
| /projects/hersones | /#shturval |
| /projects и остальные /projects/… | /#projects |
| /blogs и /blogs/… | / |

Пример: `/contacts?utm_source=yandex&yclid=123` → `/?utm_source=yandex&yclid=123#contact`. У конкретных кейсов приоритет перед общим правилом /projects. POST-запросы не перенаправляются. Остальные неизвестные пути сохраняют настоящий 404.

Общие перенаправления сохраняют удобство перехода, но не гарантируют сохранение поисковой видимости удалённых страниц: релевантность назначения важна. При появлении самостоятельной страницы `/video-content` убрать её из карты. Проверка: `curl -I 'https://petrovichbrothers.ru/video-content?utm_source=test&yclid=123'`.

## Автоматическая сборка и публикация

Workflow `.github/workflows/site.yml`:

- Pull request в `main`: установка зависимостей, синтаксис, тесты, production-сборка и проверка ресурсов. Секреты сервера этому заданию не передаются.
- Push в `main` (включая merge PR): те же проверки, затем публикация. Ручной `Run workflow` работает для `main`.
- Деплои идут последовательно. Устаревший commit не публикуется поверх более свежего `main`.
- Кандидат запускается без секретов и внешней сети. Проверяются версия, страницы, CSS/JS, 301 и рекламные метки, 404, Range видео и отклонение неверной формы без отправки сообщения.
- После переключения повторяются HTTP-проверки, включая боевой HTTPS-адрес. При ошибке восстанавливаются прежний image и его compose-конфигурация. Архив, /pb-search, почта и маршруты Traefik не меняются.

Смотреть результат: вкладка Actions → **Check and publish site**. Если проверки красные, новая версия не публикуется. Статус `Skipping superseded commit` означает, что сервер уже увидел более свежий main; актуальный запуск нужно проверить отдельно.

Серверный вход: отдельный пользователь `pb-website-deploy`, без группы docker и интерактивного доступа. Ключ разрешает только команду `deploy <40-символьный SHA>`. Root-owned `/usr/local/libexec/pb-website-ssh` проверяет команду, а `/usr/local/sbin/pb-website-receive` получает только текущий main публичного репозитория и держит блокировку публикации. Их исходники: `deploy/ssh-command.sh` и `deploy/receive.sh`. Изменения этих двух установленных файлов требуют отдельного обновления администратором; обычный main их не перезаписывает.

Секреты репозитория Actions: `PB_DEPLOY_SSH_KEY` (отдельный закрытый deploy-ключ) и `PB_DEPLOY_KNOWN_HOSTS` (проверенный публичный ключ сервера). Основные SSH-ключи администратора не используются. SMTP/Telegram остаются только на сервере. Приватный deploy-ключ не хранится в Git.

Release-каталоги: `/srv/docker/sites/petrovich-clean-webpage/releases/<полный SHA>`. Текущая версия: ссылка `current`; состояние и параметры отката: `state/last-deployment.json`. В HTTP-заголовке `X-Site-Release` находится полный SHA.

Для ручного отката администратор использует `previousImage` и `previousCompose` из файла состояния: `PB_RELEASE=<previousImage> docker compose -f <previousCompose> up -d --no-deps web`, затем проверяет сайт и актуализирует указатель current. Не менять глобальные маршруты и не запускать `docker compose down` для этой операции.

## Собственная аналитика PB Search

`fresh/cookies.js` подключает существующий `/pb-search/t/script.js` на основном домене и www. Скрипт считает время просмотра/активности, прокрутку, контакты и просмотр видео; поддерживает атрибуцию `pb_link`/`pb_click`. Коллектор остаётся `/pb-search/t/v1` в существующем PB Search. Содержимое форм не передаётся. Собственный счётчик не загружается на localhost, preview, old, GitHub Pages, в /pb-search и при Do Not Track. Метрика Яндекса подключается отдельно.

На www в Traefik нужен только публичный маршрут `Host(www.petrovichbrothers.ru) && PathPrefix(/pb-search/t/)` к `pb-crm` с существующими middleware `crm-strip`, `crm-headers` и `security`. Остальная CRM на www не открывается. Маршрут основного домена уже существовал. Тесты счётчиков используют заглушки и не записывают искусственные посещения.

Поясняющие HTML-комментарии удалены из исходных страниц; сборка также удаляет новые HTML-комментарии перед публикацией. Комментарии лицензий сторонних JS-библиотек сохраняются.
