# Petrovich Brothers

Сайт на HTML, CSS и обычном JavaScript. Vue и Nuxt не нужны: сервер отдаёт готовые страницы, а JavaScript отвечает за видео, анимации и формы. Единственная npm-зависимость — Nodemailer на сервере. Дизайн и тексты редактируются в исходных HTML/CSS/JS; `dist/` генерируется автоматически.

## Локально

Нужен Node.js 22.14 или новее.

```sh
npm ci
cp .env.example .env
npm run dev
```

Открыть http://127.0.0.1:5173/. Без реквизитов доставки форма вернёт понятную ошибку и не покажет ложный успех. Секреты в `.env` не попадают в Git, сборку и публичные файлы. Существующие переменные `NUXT_SMTP_*`, `NUXT_TELEGRAM_*`, `NUXT_CONTACT_RECIPIENTS` тоже поддерживаются для перехода со старого backend.

## Проверка и сборка

```sh
npm run check
npm test
npm run build
NODE_ENV=production npm start
```

Тесты используют подставную доставку: сообщения не отправляются. Сборка содержит только новый сайт и его медиа, без старых версий, инструментов, `.git` и серверных файлов. Она добавляет версии к ресурсам и готовит gzip/Brotli для текста. Сервер поддерживает ETag, HEAD, перемотку видео через Range и корректный 404. На production он раздаёт только `dist/` и `/api/contact`.

## Работа вдвоём через GitHub

Основной репозиторий: https://github.com/lucky-strike7/petrovich-clean-webpage. Общая актуальная версия — `main`. Для push нужен доступ на запись от владельца.

Перед новой работой:

```sh
git switch main
npm run update
git switch -c codex/my-change
```

После изменений:

```sh
npm run check
npm test
npm run build
git add <конкретные-изменённые-файлы>
git commit -m "Описание изменения"
git push -u origin codex/my-change
```

Создать pull request в `main`. После объединения Артём и Арсений обновляют свои локальные `main` командой `npm run update`. Она откажется работать при незакоммиченных файлах, в другой ветке или при расходящейся истории; force/reset/stash автоматически не применяются. Для получения свежего `main` в уже начатую рабочую ветку: `git fetch origin`, затем `git merge origin/main`, разрешить возможные конфликты и повторить проверки. Пуш рабочей ветки не публикует сайт.

Не меняйте исходники внутри `dist/` и не копируйте правки из старого сайта обратно в этот репозиторий. Все изменения нового сайта живут здесь.

## Форма

`POST /api/contact`, JSON `{ "phone": "+79150000000", "consent": true }`. Успех — только HTTP 200 и `success: true` после подтверждения хотя бы одного канала доставки. Неверные данные, отсутствие согласия, чужой Origin, слишком большой запрос и превышение лимита возвращают ошибку. Клиент блокирует повторный submit на время запроса.

В `.env` заполнить SMTP и/или Telegram. Не вставлять токены в HTML или JavaScript. По умолчанию используется реальный адрес соединения. `CONTACT_TRUST_PROXY=true` включать только за доверенным reverse proxy, который очищает входящие forwarded-заголовки; порт приложения не публиковать напрямую. Лимиты хранятся в памяти одного процесса; перед несколькими репликами потребуется общий limiter.

## Метрика

Сохранён счётчик **46078563**. Он запускается после согласия только на `petrovichbrothers.ru` и `www.petrovichbrothers.ru`; localhost, GitHub Pages и тестовые поддомены исключены. При выборе «Без аналитики» счётчик не загружается. Вебвизор не записывает клавиши поля телефона (`ym-disable-keys`). В параметры целей не передаются телефон или данные заявки.

Проверить/добавить в кабинете цели типа «Целевое событие» с идентификаторами:

- `callback_success` — подтверждённая отправка заявки;
- `contact_telegram`, `contact_phone`, `contact_email` — переход к контакту (ещё не обращение);
- `video_open` — открытие обзора.

Источник API: https://yandex.ru/support/metrica/ru/objects/reachgoal. Код событий готов; создание целей и фактическое получение событий в аккаунте требуют отдельной проверки на боевом домене. Cookie-уведомление и опубликованная политика должны оставаться согласованными при дальнейших изменениях.

## Размещение

Есть Dockerfile с Node 24 и отдельной production-стадией. Собрать `docker build -t petrovich-static:<commit> .`, передать секреты окружением или защищённым env-file и поставить за существующим HTTPS reverse proxy. Контейнер слушает 3000; наружу — только proxy. Историю счётчика и существующую почту не менять.

До переключения проверить на отдельном адресе: главную, кейс, документы, медиа, мобильную шторку, работу клавиатуры, ошибку формы и согласованную контрольную доставку. Старые страницы по решению владельца не входят в новый сайт; неизвестные URL получают настоящий 404. Служебные приложения вроде `/pb-search`, если они размещены отдельно, не удалять вместе с каталогом старого сайта. Сохранить предыдущий image/release для отката. Автоматического деплоя из GitHub в этой настройке нет.
